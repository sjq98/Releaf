# Inventory Dashboard

The **Inventory analysis** sidebar entry opens a live, read-only warehouse dashboard.
It is also the default view when opening the workspace without a specific view link.
Both administrators and members can read it. Only administrators maintain products,
warehouses, stock settings, table definitions and generic records; members continue
to use the assigned-approver document workflows.

## Views and Filters

- Inclusive month range, up to 24 months; default is the latest six Singapore calendar months.
- Warehouse, product and unit filters. Product selection sets its matching unit.
- Current stock, low-stock count and posted inbound/outbound document counts.
- Separate inbound and outbound monthly quantity curves with an accessible data table.
- Current stock/minimum/shortage table, low-stock highlighting and a low-stock-only filter.
- Monthly opening/closing stock, quantity-based turnover, inbound/outbound and signed adjustments.
- Paginated tables, links to underlying product/stock records and CSV report export.

Units are never added together. Kilograms and pieces require separate selections.
Current stock alerts reflect the inventory table's live balance; changing the
historical month range does not turn alerts into historical snapshots. Document
counts and monthly quantities use the selected period and matching product/unit.
Draft, rejected, pending and approved-but-unposted requests do not change quantities.

## Calculations

The report reads the complete immutable movement ledger, not the recent-activity
feed capped at 1,000 rows. It does not write summary rows or change business records.
Decimal arithmetic is used for balances.

For each product/warehouse/month:

```text
closing = opening + inbound - outbound + signed adjustments
average stock = (opening + closing) / 2
quantity turnover = outbound / average stock
turnover days = calendar days in month / quantity turnover
```

Opening includes the stock's initialization quantity and all prior effective
movements. Ordinary movements use the document's posting date, including legitimate
backdated posting. Reversals use their actual execution date in Asia/Singapore and
appear as signed adjustments, preserving the original receipt/issue in its original
month. Later reversals do not rewrite historical transactions.

No outbound quantity gives turnover zero and undefined turnover days. An average
balance of zero with outbound movement gives undefined turnover and turnover days;
the UI/export leaves them blank or displays `-`, never infinity. This is a
quantity-based operational indicator, not financial inventory turnover or cost of
goods sold. Without a daily balance snapshot, it is not a daily-average calculation.

## Shared Interface

```http
GET /api/warehouse/dashboard?spaceId=default&from=2026-05&to=2026-10&unit=kg
```

Browser access requires login. Optional `warehouseId` and `productId` are record IDs
in the selected Space. Invalid ranges, foreign records, unknown units and a selected
product with an incompatible unit are rejected.

Agents call the same read-only computation:

```json
{
  "operation": "get_inventory_dashboard",
  "args": { "from": "2026-05", "to": "2026-10", "unit": "kg" }
}
```

The Agent token supplies its Space when omitted and cannot select another Space.
This read does not require a write approval or idempotency key.

## Synthetic Demonstration Data

The optional local maintenance command first creates an online SQLite backup:

```powershell
node scripts/seed-warehouse-demo.mjs --apply data/forms.sqlite --as-of 2026-10-24
```

It adds two `DEMO-` warehouses, six bakery/packaging products, twelve stock positions,
23 inbound and 23 outbound documents, 128 detail lines and 108 posted movements.
The posted sample history spans six months; extra drafts, pending, approved,
rejected and cancelled documents demonstrate workflow states without affecting
stock. One sample stock position has zero balance and eight are below their
configured thresholds.

Every business write uses the existing catalog/document/transition operations.
No direct quantity patches, invented accounting records or account/password changes
are made. When accounts exist, the seed uses an active administrator's identity;
without accounts, notes identify trusted internal demo operations. Document numbers
remain generated by the normal sequence. Notes label all generated records as
`DEMO/Dashboard sample`.

The whole seed is atomic and has a completion marker. Rerunning is a no-op and does
not overwrite manual edits. Conflicting reserved sample codes abort the operation.
The command is not exposed through HTTP or Agent tools. Synthetic stock is for
demonstration, not real business or sustainability-impact evidence; use the backup
when restoring the pre-demo local database. Local databases and backups remain
excluded from Git.
