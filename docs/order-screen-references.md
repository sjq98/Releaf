原图：`C:/Users/shaoj/AppData/Local/Temp/codex-clipboard-5ed98546-95a4-46ba-b97e-816c9aaadb59.png`

### 可见内容

截图为自上而下、箭头串联的四步流程：

| 顺序 | 标题 | 说明原文 |
| --- | --- | --- |
| 1 | WhatsApp 顾客下单 | 例如：我要两份鸡饭，一份不要辣 |
| 2 | AI Agent 订单识别 | 提取菜品、数量、备注、价格 |
| 3 | 商家订单管理后台 | 确认订单、管理库存、支付核对、销售统计 |
| 4 | 订单状态通知 | 已接单 → 制作中 → 可取餐 / 配送中 |

图中的业务关系：

```text
顾客通过 WhatsApp 表达购买需求
  -> AI 识别订单信息
  -> 商家在后台确认和管理订单
  -> 向顾客通知订单状态
```

## 用户要求与实现边界

用户明确要求：按图一的业务流程做，订单管理后台参考图二的模板；应用 UI 仍沿用 Orbyte 风格。以下是实现时补充的决策，不是截图原文：

1. AI 输出可编辑草稿，由人确认后创建订单；顾客消息和模型返回内容不直接触发保存或出入库。
2. 按用户后续澄清，具体商品、数量和制作要求写入订单备注；商品目录归库存模块，订单不提供商品选择、菜单或单价维护。订单总额由用户明确填写或从消息中有原文证据的订单总额提取，再由人确认。
3. 顾客的分份备注需要保留，例如“两份鸡饭，一份不要辣”不能丢失其中一份的独立要求。
4. 收款和开票独立记录，待收款、待开票金额从业务记录计算。
5. 按用户后续澄清，订单和库存保持独立，不关联出入库，不预留或扣减库存，也不从订单创建出库草稿。
6. 用户和 Agent 使用相同业务能力、权限和校验；Agent 不获得用户界面没有的额外业务权限。
7. WhatsApp 自动收消息和发送状态通知属于独立的渠道集成。目前的文本输入和本地通知文案不等于已接通 WhatsApp。
